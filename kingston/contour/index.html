THE CONTOUR PATTERN · DATA, CODE, REJECTS

How the Contour pattern was made

Kingston’s terrain and rivers, turned into lines by a pipeline we built. Here’s the data, the code, and the versions we threw away.

Elevation data and the real course of the creek, turned into lines by a small program: loose where the land is, calm and parallel toward the river. One red line for the Rondout.

The poster, tee and tote

The lines on the Crew car aren't decoration we picked from a catalog. They come from Kingston itself: the shape of the land along Rondout Creek, from Rosendale down to where the creek meets the Hudson. A small program turns that terrain into the pattern. Here is each step, along with the versions we threw away.

1. Data

We started from two public datasets.

  • Elevation. We used about 14 m resolution terrain tiles from the AWS Terrain Tiles open dataset, which is built on USGS 3DEP elevation data. Each pixel's color encodes a height in meters.
  • Water. We took the centerlines of the Hudson River, Rondout Creek and Esopus Creek from OpenStreetMap.

We kept a strip of land about 13 km long that follows Rondout Creek, starting a little above Rosendale and ending at the Rondout lighthouse. The strip has the same proportions as the side of the car (about 4.4 : 1). Its rear end sits upstream and its front end sits at the Hudson.

2. Contours

A contour line joins points of equal height. We traced them with marching squares, a classic algorithm that walks the elevation grid one cell at a time and finds where each height level passes between grid points. Before tracing we smoothed the terrain slightly (about 90–140 m) so the lines flow instead of jittering. The result below has a line every 10 m, with the real creek drawn in red.

It's accurate, and it looks like a hiking map. That's not what we wanted.

3. The warp

This step is what makes it ours. We don't trace the terrain directly. We trace a blend of two fields:

  1. The land: the real elevation.
  2. The flow: the distance from every point to the creek. The level lines of this field are parallel copies of the creek.

At the rear of the car the land dominates, so you see real hills and hollows around Rosendale and Eddyville. Moving forward, the blend shifts smoothly toward the flow. By the front wheel every line runs parallel and evenly spaced. The creek gets the same treatment: it follows its real meanders at the back and straightens out as it nears the Hudson.

A narrow, calm channel either side of the creek keeps any line from touching the red path.

4. The path

One line gets the accent color: Rondout Creek, from upstream to the Hudson. It's the only color on the car. Everything else is warm gray on satin charcoal.

5. The print file

The output is a clean vector SVG, measured in millimetres at real size. Each format gets stroke widths suited to how it's printed and viewed:

FormatSizeLinePath
Car side4400 × 1000 mm3.0 mm8 mm
Hood1500 × 1150 mm3.0 mm8 mm
Poster / tee457 × 610 mm (18 × 24 in)0.55 mm1.5 mm
Sticker / tote300 × 300 mm (scales to 100 mm with lines ≥ 0.3 mm)0.9 mm2.4 mm

The lines fade gently toward the rear, which keeps the busy end quiet. The colors are three variables (--contour-bg, --contour-line, --contour-path), so the brand palette can be dropped in later. Each format also has a .print.svg with the hex values flattened in for the wrap shop.

Versions we rejected

Terrain at full strength. This was the first attempt. It was far too busy, read as a map, and the lines bunched up into bright bands along the creek.

No warp. Real terrain all the way to the front. The car looks like it's covered in a map, with no sense of direction.

Pure flow. Only the distance-to-creek field. It's calm but generic, and the place is gone.

Path laid on top. We blended the terrain with plain horizontal stripes and drew the creek over them. Gray lines cross the red one, which makes the path look like an overlay instead of part of the pattern.

We also tried measuring height relative to the creek bed. That left hard seams wherever the "nearest point on the creek" jumped, so we dropped it. It's still in the code as bed_relative, switched off.

Run it yourself

python3 generate.py                       # all options, formats, mockups, story images
python3 generate.py --only B
python3 generate.py --seed 11 --lines 60 --warp 0.3 --aspect 4.4

It needs Python 3 with numpy, scipy and Pillow. PNGs are rendered with headless Chrome, and the qrcode package is installed into lib/. The raw data is cached in data/, so the run works offline and gives the same output every time.
