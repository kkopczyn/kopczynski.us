Why TradeUp

TradeUp is building the system trade-school career services runs on: placements tracked, verified and ready for an audit. I've spent the last year building the same kind of system on the employer side of the trades.

Titan ran daily operations for multi-location home-services companies, mostly franchise locations in window cleaning, painting and similar field work, across two franchise systems and 120+ locations.

Three parts of it map closely to what TradeUp needs, below.

Relevant work

Technician recruiting by text

An applicant gets a text within minutes of applying. An AI agent runs the screening conversation, nudges people who go quiet and opens a thread for the hiring manager with a score and a summary. Every applicant gets screened, the score only sets priority. Questions that need exact wording, like work authorization, go out word for word, so every transcript is consistent.

Cost per hire went from about $1,000 to $100 to $150.

For TradeUp: the same engine could confirm graduate employment by text and then confirm with the employer, with both answers logged for the placement file.

Data pipelines people trust

Titan takes webhooks from Jobber and ServiceMinder into Postgres and BigQuery in real time, reconciles nightly and keeps every version of every record, so every number can be traced back. It feeds a daily dashboard and a twice-daily email for owners.

Before Titan, at Croud, I built a guided data-entry tool for campaign naming that cut my team's error-fixing time by about 80% and became a self-serve tool worth $5M in annualized savings.

For TradeUp: placement rates by program and campus that hold up when an auditor asks where each number came from.

A build system for a small team

I run 80+ AI coding agents in parallel, and every change goes around the same loop. Feedback and requests come in, each change gets a written plan, agents build it, and four AI reviewers, 21 automated checks and a live preview check it before my approval and a merge queue. Deploys test themselves and roll back if something breaks, and an overnight scan has a tested fix ready by morning.

About 975 changes shipped this way, replacing a roughly 7-person engineering team. A senior engineering leader at Adobe told me they are building similar tooling internally.

For TradeUp: a part-time CTO with this pipeline ships like a full team, with a security review on every change.

Agents with guardrails

Titan's chat and agent engine has write tools only where enabled, approvals by risk and role, spend caps and an emergency off switch. With student records, that's where I'd start.

How it could work

  1. A 30-minute working session

    Bring one problem, for example how to verify placements, and we work it out together on the call. Afterwards you get a write-up of the whole thing.

  2. 30-day technical sprint

    Week one: an architecture and security review of the product and data model, with findings ranked by risk. Weeks one and two: set up the build pipeline on your repo, owned by your CTO. Weeks two to four: ship one feature live for your design partner, for example graduate employment verification by text.

  3. Then 1 to 2 days a week

    Fractional engineering lead alongside your CTO: architecture, the data and verification layer, AI features, code review.
